    sidescanpy.processing.interpolate¶

    Interpolate auxiliary records onto per-ping timestamps.

    The converter populates per-ping fields (latitude, heading_deg, etc.) on each SideScanFrequencyChannel from the embedded values in SonarDataMessage. For many quantities those embedded values are stale — they're the most-recent auxiliary reading at the moment the ping was recorded, not interpolated to the ping's exact timestamp.

    This module provides higher-precision per-ping values by interpolating each frequency channel's ping times against the survey's auxiliary records.

    Aux records are themselves often sample-and-hold (each entry repeats the latest sensor value until the sensor updates). By default (held_values="fixes") each record is first reduced to its real fixes with :func:~sidescanpy.processing.aux_fixes.held_value_fixes, so the interpolated track is smooth instead of stair-stepped. When a field has no usable aux source, the channel's own per-ping values (also typically held) are reduced the same way and interpolated (per_ping_fallback).

    Two layers:

    • interpolate_aux_onto_pings(survey, ...) — top-level entrypoint. Iterates the default field-to-aux mapping (or a user override) and applies interpolation per channel.

    • interpolate_onto_channel(channel, source, field_map, ...) — lower level. Takes any xr.Dataset with a time coordinate as the source, enabling external data (e.g. a separately recorded GPS log) to drive per-ping field updates.

    2026 rshomberg@uri.edu

    interpolate_aux_onto_pings ¶

    interpolate_aux_onto_pings(
    survey: SideScanSurvey,
    *,
    fields: dict[str, tuple[str, str]] | None = None,
    method: str = "linear",
    extrapolation: Literal[
        "clamp", "linear", "nan"
    ] = "clamp",
    drop_invalid: bool = True,
    force: bool = False,
    in_place: bool = False,
    held_values: Literal["fixes", "raw"] = "fixes",
    max_hold_s: float = 2.0,
    per_ping_fallback: bool = True,
    groups: Sequence[Sequence[str]] | None = None,
    merge_window_s: MergeWindow = None,
) -> SideScanSurvey

    Update per-ping fields on every frequency channel by interpolating the survey's auxiliary records onto each ping's timestamp.

    Parameters:

    Name Type Description Default
    survey SideScanSurvey

    Survey to operate on.

    		 required
    fields dict

    Mapping {per_ping_field: (aux_name, aux_var)}. Overrides the default in DEFAULT_FIELD_SOURCES. Use this to interpolate only a subset of fields, or to point a field at a non-default source.

    		 None
    method str

    Interpolation method passed to xarray.Dataset.interp — "linear", "nearest", "cubic", etc.

    		 "linear"
    extrapolation (clamp, linear, nan)

    Behavior when a ping's timestamp falls outside the aux record's time range. "clamp" holds the boundary value; "linear" extrapolates the slope; "nan" writes NaN.

    		 "clamp"
    drop_invalid bool

    If True, drop rows where the aux source variable is NaN before interpolating. Avoids NaN propagation through the interpolated result. Set False to require the source be clean. With held_values="fixes" NaN entries are never fixes and are always dropped.

    		 True
    force bool

    If True, attempt interpolation even when the aux record is empty or absent and no per-ping fallback applies: the per-ping field receives NaN. If False (default), the field is left unchanged and a warning is logged.

    		 False
    in_place bool

    If True, mutate survey in place and return it. If False, return a new SideScanSurvey leaving the input untouched.

    		 False
    held_values (fixes, raw)

    "fixes" reduces each aux record to its real fixes first (:func:~sidescanpy.processing.aux_fixes.held_value_fixes): many recorders log the latest GPS or attitude value at every ping or packet, and interpolating between those repeated entries keeps the stair-steps (consecutive pings stack on one position, then jump). "raw" interpolates the entries as logged (the only behavior up to 0.7.2).

    		 "fixes"
    max_hold_s float

    With held_values="fixes": a value unchanged for longer than this is kept flat across the hold (a stop, or a sensor dropout) rather than ramped through it. See :func:~sidescanpy.processing.aux_fixes.held_value_fixes.

    		 2.0
    per_ping_fallback bool

    With held_values="fixes": when a field's aux record is absent or empty, or its variable is missing or all NaN, reduce the channel's own per-ping values of that field (against the ping times) to fixes and interpolate those instead. Per-ping values that never repeat are returned unchanged. The fields filled this way are recorded in the history entry. No effect with held_values="raw".

    		 True
    groups sequence of sequence of str

    With held_values="fixes": variables that update together, passed to :func:~sidescanpy.processing.aux_fixes.held_value_fixes for each record (by aux variable name; for the per-ping fallback, by per-ping field name). A group applies to a record only when all its variables are in it, so groups=[POSITION_GROUP] joins latitude and longitude in the navigation record and leaves attitude alone. Default: every variable is its own group.

    		 None
    merge_window_s float or mapping of str to float

    With held_values="fixes": merge changes at most this many seconds apart into one update event, for recorders that log one sensor update over consecutive entries. A float applies to every group of every record; a mapping by aux variable name (for the per-ping fallback, by per-ping field name), such as {"latitude": 0.15, "longitude": 0.15}, only to those variables' groups. See :func:~sidescanpy.processing.aux_fixes.held_value_fixes. Default None: no merging.

    		 None

    Returns:

    Type Description
    SideScanSurvey

    Survey with updated per-ping fields. Each touched frequency channel gets a new processing_history entry.

    Raises:

    Type Description
    ValueError

    If fields references an unknown aux record name. If extrapolation or held_values is not one of the supported values, or max_hold_s or merge_window_s is out of range.

    interpolate_aux_onto_dataset ¶

    interpolate_aux_onto_dataset(
    ds: Dataset,
    aux: SideScanSurvey,
    *,
    fields: dict[str, tuple[str, str]] | None = None,
    method: str = "linear",
    extrapolation: Literal[
        "clamp", "linear", "nan"
    ] = "clamp",
    drop_invalid: bool = True,
    force: bool = False,
    held_values: Literal["fixes", "raw"] = "fixes",
    max_hold_s: float = 2.0,
    per_ping_fallback: bool = True,
    groups: Sequence[Sequence[str]] | None = None,
    merge_window_s: MergeWindow = None,
) -> xr.Dataset

    One frequency channel dataset's per-ping fields, interpolated from aux's auxiliary records (the "interpolate_aux" step).

    Same parameters as :func:interpolate_aux_onto_pings, but for a single dataset (or a ping slice of one) with the survey supplying the aux records. Always appends an "interpolate_aux" history record (with the fields actually updated, possibly none, held_values, max_hold_s, per_ping_fallback, groups, merge_window_s and the fields filled from per-ping values as per_ping_fallback_fields) so the step is not re-run.

    For the per-ping fallback on a ping slice, the per-ping values come from the matching whole channel in aux (same freq_hz_start, same times at the slice's ping coordinates) when there is one, so a chunked run gives the same result as an unchunked one.

    interpolate_onto_channel ¶

    interpolate_onto_channel(
    channel: SideScanFrequencyChannel,
    source: Dataset,
    *,
    field_map: dict[str, str],
    method: str = "linear",
    extrapolation: Literal[
        "clamp", "linear", "nan"
    ] = "clamp",
    drop_invalid: bool = True,
    record_history: bool = True,
) -> SideScanFrequencyChannel

    Interpolate variables from an arbitrary source dataset onto one frequency channel's ping times.

    The source entries are used as given. For a sample-and-hold source (the latest value repeated until the sensor updates), pass held_value_fixes(source) to interpolate between real fixes.

    Parameters:

    Name Type Description Default
    channel SideScanFrequencyChannel

    Target channel.

    		 required
    source Dataset

    Source dataset. Must have a time coordinate (datetime64-typed) and a single non-time dimension over which the variables are defined. Variables named in field_map values must exist.

    		 required
    field_map dict

    {per_ping_field: source_var_name}.

    		 required
    method str

    Interpolation method passed to xarray.Dataset.interp.

    		 "linear"
    extrapolation (clamp, linear, nan)
    		"clamp"
    drop_invalid bool

    Drop NaN rows from each source variable before interpolating.

    		 True
    record_history bool

    If True, append a processing_history entry to the resulting dataset. Set False when called as part of a higher-level pipeline that records history once.

    		 True

    Returns:

    Type Description
    SideScanFrequencyChannel

    New channel with updated per-ping fields. Original is not modified.
