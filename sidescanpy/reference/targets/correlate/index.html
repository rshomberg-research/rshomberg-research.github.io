    sidescanpy.targets.correlate¶

    Resolve target positions and clock offsets against converted .ss.h5 files.

    Catalog formats that store no absolute position (the Klein .tgt reader in :mod:sidescanpy.io.sdf.targets) are located here against per-ping times of converted surveys. For Klein catalogs use :func:resolve_targets_by_catalog_ping, which matches the catalog's own ping time and number exactly; the pick-timestamp functions (with optional constant clock-offset calibration) match the later save time and are only a fallback for catalogs without those fields. Also provides position-based correlation of any target to a ping in a directory of converted surveys, and projection of a target onto another frequency channel.

    2026 rshomberg@uri.edu

    calibrate_clock_offset ¶

    calibrate_clock_offset(
    ss_h5_dir: str | Path, *, local_utc_offset_hours: float
) -> float

    Derive the constant epoch-shift between each .ss.h5's (possibly corrupted) ping clock and its filename-embedded true local start time.

    Filenames are expected to embed <YYMMDD><HHMMSS> local start time (matches Klein SDF's own sonar_data<YYMMDD><HHMMSS>.sdf naming, preserved through conversion). Returns the median offset (seconds, corrupted minus true) across every file found in ss_h5_dir, logging each file's individual estimate so a bad calibration (large spread => the offset isn't actually constant for this survey) is visible rather than silently trusted.

    Parameters:

    Name Type Description Default
    ss_h5_dir str or Path
    		required
    local_utc_offset_hours float

    Required keyword. Local-time-to-UTC offset (hours to add to the filename's embedded local time to get UTC). Use the offset that was actually in effect at the survey's location/date -- there is deliberately no default.

    		 required

    Returns:

    Type Description
    float

    Median offset in seconds (corrupted ping time - true start time).

    Raises:

    Type Description
    RuntimeError

    If no file in ss_h5_dir matched the expected filename pattern.

    resolve_targets_offset_corrected ¶

    resolve_targets_offset_corrected(
    targets: list[Target],
    ss_h5_dir: str | Path,
    offset_s: float,
    *,
    max_time_delta_s: float = 300.0,
) -> list[Target]

    Resolve position (plus altitude/speed) for every target in targets using a known constant clock offset (see :func:calibrate_clock_offset).

    Enriches each matched target with altitude_m/speed_mps/ meters_per_ping/ground_range_m in extra_attributes — all approximations from the nearest matched ping, not per-sample measurements, and constant across a target's ~256-ping window. position_confidence stays "unknown" regardless of match quality, matching :func:resolve_target_position's convention. Targets with no pick_timestamp, or whose nearest match (across every .ss.h5 file in ss_h5_dir) is farther than 20 * max_time_delta_s away, are returned unchanged.

    resolve_targets_nearest_ping ¶

    resolve_targets_nearest_ping(
    targets: list[Target],
    ss_h5_dir: str | Path,
    *,
    max_time_delta_s: float = 300.0,
) -> list[Target]

    Resolve position for every target in targets via plain (no clock-offset) nearest-ping matching, checking every .ss.h5 file and every frequency channel in ss_h5_dir and keeping whichever match lands closest in time.

    Thin batch wrapper around :func:resolve_target_position — use :func:resolve_targets_offset_corrected instead when the survey is known to need clock-offset correction (see that function and :func:calibrate_clock_offset).

    resolve_targets_by_catalog_ping ¶

    resolve_targets_by_catalog_ping(
    targets: list[Target],
    ss_h5_dir: str | Path,
    *,
    max_time_delta_s: float = 1.5,
) -> list[Target]

    Place targets at the ping their catalog names (Klein .tgt).

    Klein catalogs store the target ping's own time and ping number (extra_attributes["catalog_ping_time"] / ["catalog_ping_number"], see :mod:sidescanpy.io.sdf.targets) on the sonar's clock, the same clock as the converted pings. Matching them needs no clock offset and, unlike pick_timestamp (the later save time), identifies the target's ping exactly.

    For each target, the pings of every .ss.h5 in ss_h5_dir within max_time_delta_s of the catalog time are searched for the catalog ping number (ping counters restart after recording gaps, so the time window is what makes the number unique). If the number is not there, the nearest ping in time within the window is used and recorded as position_source="catalog_ping_time".

    Sets latitude/longitude to that ping's position (the vehicle position at the target ping, not the target's own seafloor position) and position_confidence="approximate", and records ss_h5 (file stem), ping_index (file-local), ping_number, position_source ("catalog_ping"), position_time_delta_s, altitude_m, ground_range_m/ground_range_clipped (from range_m), and speed_mps/meters_per_ping in extra_attributes.

    Parameters:

    Name Type Description Default
    targets list of Target
    		required
    ss_h5_dir str or Path

    Directory of converted .ss.h5 files.

    		 required
    max_time_delta_s float

    Half-width of the time window around the catalog time (the catalog time has 1 s resolution).

    		 1.5

    Returns:

    Type Description
    list of Target

    Same order as targets. Targets without catalog fields, or whose catalog time is in no file (for example picked while not logging), are returned unchanged.

    project_target_to_frequency ¶

    project_target_to_frequency(
    target: Target,
    source_mps: float,
    target_mps: float,
    *,
    n_samples: int | None = None,
) -> Target | None

    Re-express target's position on a different frequency channel of the same survey, using the one thing both channels share exactly: the physical world.

    A source catalog (EdgeTech Discover, Klein SonarWiz) only ever marks a contact against the one frequency channel it was picked on — there is no "also visible on the other channel" field. But ping (both channels are pinged in lockstep — the same physical vessel position, identical ping count per channel within one file) and the physical slant range a sample represents (sample * meters_per_sample) are both real, channel-independent quantities. So the target's true position on the untagged channel is recoverable: convert its sample index to a physical slant range using the source channel's own meters/sample, then back to a sample index using the target channel's — same ping, same side, no catalog entry needed for that channel at all.

    ping/channel/every other field are carried through unchanged (replace) — only sample moves, plus extra_attributes["projected_from_mps"] recording the source resolution, so a caller/renderer can tell a real catalog mark apart from one recovered this way (e.g. to draw it with a different box style) without losing the fact that it's the same real contact.

    Returns None (not a clamped/guessed value) if the projected sample would land at or past n_samples — a real, physical consequence of the two channels recording different maximum ranges, not a placement bug: the contact genuinely sits beyond the other channel's recorded window and has no honest position to report there. Only checked when n_samples is given.

    correlate_target ¶

    correlate_target(
    target: Target,
    index: dict[Path, dict],
    max_dist_m: float,
) -> PositionMatch | None

    Locate target in the surveys described by index.

    The frequency channel is chosen per file with :func:match_frequency using target.extra_attributes["ping_meters_per_sample"] when present.

    Strategies are tried in order:

    1. Resolved ping: a target placed by :func:resolve_targets_by_catalog_ping records its file stem (extra_attributes["ss_h5"]) and file-local ping_index; when that file is in index and the ping in range, it is used as is (distance 0). Navigation fixes often repeat over several pings, so the nearest position alone can be several pings off.
    2. Position: the nearest ping by geodesic distance on the WGS84 ellipsoid (:meth:pyproj.Geod.inv) over all files, accepted if within max_dist_m. Pings without a position fix are skipped.
    3. Ping number (only if step 1 fails or the target has no lat/lon): target.ping is a mission-global ping number, converted to a file-local index via each channel's ping_start. Accepted only when exactly one file's range contains it; zero or several candidates return None rather than guess. This recovers catalogs that carry only a pixel-derived ping and no (or a less precise) GPS position.

    Name Type Description Default
    target Target
    		required
    index dict

    From :func:build_position_index.

    		 required
    max_dist_m float

    Maximum distance for a position match.

    		 required

    Returns:

    Type Description
    PositionMatch or None
