Processing#

sidescanpy.processing corrects, slices and measures frequency-channel datasets. Every function takes and returns an xr.Dataset (the corrections also take a whole survey); the input is never modified. Getting started runs the default correction on a public line, and Correct a line adds the bottom track.

Corrections#

Each correction is a function. Call them in order on a whole survey (every frequency is corrected and a new survey returned) or on one frequency dataset:

from sidescanpy.processing import (
    altitude_from_bottom_track,
    apply_tvg,
    compute_geometric_ranges,
    compute_georeferencing,
    interpolate_aux_onto_pings,
)

survey = interpolate_aux_onto_pings(survey)        # navigation and attitude onto pings
survey = altitude_from_bottom_track(survey)        # only if the file has no altitude
survey = apply_tvg(survey, spreading_loss_db=30)   # spreading and absorption
survey = compute_geometric_ranges(survey)          # slant and ground range
survey = compute_georeferencing(survey)            # latitude and longitude per sample

Every call records itself in the dataset’s processing_history with the parameters it used, and the input is never modified. Leave a call out to skip that correction, or put your own function in the chain. The radiometric corrections (apply_tvg, the range correction) refuse to run twice on the same data, because their gains would stack; to change a TVG recipe, invert the dataset first. The other functions recompute when called again.

Running steps by name#

The same corrections can be run from a list of step names, which suits a config file or the command line (sidescan-correct --steps):

Function

Applies steps to

correct(ds, steps, params, aux=None, force=False)

one frequency channel

correct_survey(survey, steps, params, frequency_params=None, force=False)

every channel of a survey (feeds the survey’s navigation/attitude records to interpolate_aux)

correct_file(path, steps, params, out_path=None, chunk_pings=None)

a .ss.h5 file, written atomically (in place by default), optionally in ping chunks to bound memory

 
from sidescanpy.processing import correct_survey

survey = correct_survey(survey, ["interpolate_aux", "tvg", "geometric", "georef"],
                        params={"tvg": {"spreading_loss_db": 30.0}})

Use correct_file for files too large for memory, and for adding several steps to a file: it applies them in one pass, which is much faster than writing the file after each step.

Rules#

These apply to step lists (correct, correct_survey, correct_file).

  • Skip a step by leaving it out. params may only name steps that are in steps; a typo raises ValueError, and an unknown parameter raises TypeError. Both are checked before anything runs.

  • Custom steps. Any callable fn(ds, **params) -> ds, or Step(name, fn), can be a step. It is recorded in history like a built-in. Give each one a distinct name; lambdas are rejected.

  • Idempotent. A step already recorded in processing_history is skipped, so re-running is a no-op. force=True re-applies it; a radiometric step is inverted first, so new parameters replace the old ones instead of stacking.

  • History. Each applied step appends {"step", "params", "function", "version", "timestamp_utc"} with the parameters actually used.

  • No raw copy. Corrections modify backscatter_intensity in place. invert(ds) undoes recorded steps, and uncorrected_backscatter(ds) returns the signal with every radiometric step undone. processing_level(ds) reports the latest applied level (raw, tvg, geometric, range_correction, georef).

TVG#

apply_tvg adds the two-way propagation loss back:

  • Spreading: spreading_loss_db * log10(R). The default, 30, models the insonified seafloor patch growing in proportion to range: two-way spherical spreading (40) less 10 log R (e.g. J. Mar. Sci. Eng. 2017, 5(4), 54). Which fits real data varies; measure it per survey with analysis.fit_range_decay (pass the same spreading_loss_db) and set the coefficient in the config. 40 was the default in 0.7.0-0.7.5 and 20 (one-way spreading) before 0.7.0; files corrected with either record the value in their history, so invert() still undoes them exactly.

  • Absorption: 2 * alpha * R. When absorption_db_per_m is not given, alpha comes from the Francois-Garrison model for the channel’s frequency (francois_garrison_absorption_db_per_m), using temperature_c, salinity_psu, depth_m and ph (defaults 10 °C, 35 psu, 10 m, pH 8). The resolved value is recorded in history.

Linear amplitude is converted to dB as 20 * log10(clip(x, 1e-6)) first, so exact zeros map to about -120 dB. A zero or missing sound velocity falls back to 1500 m/s. Setting a term to 0 turns it off, which is how to avoid correcting a loss the hardware already compensated.

References:

  • R. E. Francois and G. R. Garrison, “Sound absorption based on ocean measurements: Part I: Pure water and magnesium sulfate contributions,” J. Acoust. Soc. Am. 72(3), 896-907 (1982).

  • R. E. Francois and G. R. Garrison, “Sound absorption based on ocean measurements: Part II: Boric acid contribution and equation for total absorption,” J. Acoust. Soc. Am. 72(6), 1879-1890 (1982).

Geometric ranges#

compute_geometric_ranges adds per-sample slant_range_m, ground_range_m, across_track_m (port negative, starboard positive, pitch-corrected) and related variables:

  • Slant range: sample * sound_vel / (2 * sample_rate), from the absolute sample coordinate, so a dataset trimmed of leading samples keeps its true ranges.

  • Ground range (flat bottom): sqrt(slant² - altitude²) where slant > altitude, NaN in the water column. A ping with NaN altitude gets NaN ground range (and no georeferenced position); altitude 0 gives ground range equal to slant range. Both are logged at WARNING.

Altitude from the bottom track#

Some recordings have no usable altitude: no altimeter, no bottom lock, or a recorder that writes 0. altitude_from_bottom_track (the bottom_track step) measures it from the data: the onset of the bottom return on each channel (detect_first_bottom_return on the uncorrected amplitude, refined to the half-rise sample), the nearer channel, in metres of slant range. By default it fills only pings whose altitude_m is NaN or <= 0; max_diff_m also replaces recorded values that disagree with the track by more than that (a lost lock that still writes a value), and replace="all" replaces every ping.

The return must stay above threshold for min_return_m (default 5 m) of slant range, of which min_return_fraction (default 70 %) must be above: a transmit burst lasts a metre or two, a seabed return tens of metres, and the fraction lets shadows in a rough seabed through. On public test files with a recorded altimeter (Benthos SIS-1624, about 30 m altitude) the tracked value agreed to within 0.2 m for 90 % of pings. The first return comes from the beam’s near edge, so on sloping or very shallow seabed the tracked value is the slant range to the nearest bottom point, a little above the true altitude (+0.6 m at 1.7 m altitude on a Klein 3000 file).

Georeferencing#

compute_georeferencing adds latitude_per_sample and longitude_per_sample from the per-ping position, heading and across-track offset on the WGS84 ellipsoid.

Navigation interpolation#

interpolate_aux_onto_pings (and the interpolate_aux step) replaces per-ping latitude, longitude, heading, roll, pitch and heave with values interpolated from the survey’s navigation and attitude records (DEFAULT_FIELD_SOURCES). Altitude, depth and sound velocity are live sensor readings and are not interpolated by default; see JSF aux source selection. interpolate_onto_channel takes any external xr.Dataset with a time coordinate, such as a separate GPS log.

Sample-and-hold aux streams. Recorders commonly log the latest GPS fix or attitude value at every ping or packet, so a value repeats until the sensor updates (a ~1 Hz GPS under ~10 Hz pings repeats each position about ten times; attitude streams repeat on their own schedules). Interpolating those entries as logged keeps the stair-steps: consecutive pings stack on one position, then jump, which shows up in ground-range and georeferenced output. By default (held_values="fixes") each aux record is first reduced with held_value_fixes:

  • every variable is its own group, latitude and longitude included, since some recorders log the two coordinates of one fix in separate entries (groups=[POSITION_GROUP] joins them);

  • an entry is a fix when its group’s value differs from the previous finite entry; NaN entries are never fixes;

  • a fix that ends a held run is placed midway between the last held entry and the changed one (the update arrived in between); a fix right after another fix keeps its own time, so a stream with no repeats is unchanged;

  • duplicate timestamps collapse to the last entry logged at that time;

  • a value held for longer than max_hold_s (default 2 s) also keeps an anchor at its last entry, so the track stays flat across a real stop or a sensor dropout instead of ramping through it.

Some recorders also spread one sensor update over consecutive entries: the bulk change, then a small follow-up (a few cm) one entry later, then nothing until the next update. Every change then becomes a fix, two fixes land one entry apart, and the interpolated speed swings between a fraction of and several times the true speed. merge_window_s (default None, no merging) collapses changes of one group that are at most that many seconds apart (chained) into one update event:

  • the event carries the group’s value after its last change;

  • it is timed like a fix at its first change (the midpoint after a hold): the update started reaching the log there, and the follow-ups complete it rather than report new motion. This gives every event the same latency, whereas timing at the last change would add a delay that depends on how many entries the update spread over;

  • a max_hold_s hold is measured from the event’s last change;

  • groups merge independently, and the record’s first entry is never merged.

Choose the window longer than the follow-up delay (one entry) and shorter than the gap from the follow-up to the next update; about two log intervals usually fits. Too long a window chains successive updates into one event, which is far worse than no merging.

A float applies to every group of every record, so a window sized for a ~3 Hz GPS also chains the changes of a ~10 Hz roll sensor; a mapping by variable name, such as merge_window_s={"latitude": 0.15, "longitude": 0.15}, merges only the groups holding those variables (a group takes the smallest window of its variables). A WARNING is logged when an event combines more than five changes.

To choose the window, aux_update_events(record, groups=..., merge_window_s=...) reports, per group, the entries, raw changes, events after merging, the percentiles (p5–p95) of the gaps between changes and between events, in entries and seconds, and the fraction of changes that fall within the window of the previous one. Split updates show as bimodal change gaps (a peak at 1 entry and one at the update interval) that become unimodal event gaps once merged. On a line running mostly north–south one coordinate barely changes, so per-coordinate change counts say little about how updates are split; check the joint group (groups=[POSITION_GROUP]) too.

The step’s groups parameter is passed to held_value_fixes for each record, applying a group only where all its variables exist, so groups=[POSITION_GROUP] joins latitude and longitude in the navigation record and leaves attitude alone.

When a field has no usable aux source (record absent or empty, variable missing or all NaN), per_ping_fallback=True (default) reduces the channel’s own per-ping values the same way and interpolates those. The step’s history record carries held_values, max_hold_s, per_ping_fallback, per_ping_fallback_fields, groups and merge_window_s. held_values="raw" interpolates the entries as logged, as in 0.7.2 and earlier.

The step is skipped on files whose history already records it; re-convert, or correct with force=True, to apply the reduction to a file corrected before.

Segments#

find_segments splits a file into contiguous segments and labels each one clean or excluded, from gaps in time or position (detect_gaps), hardware setting changes (detect_setting_changes), dropout or garbage runs (detect_garbage_runs) and attitude instability (detect_unstable_spans). split_by_segments returns one sub-survey per clean segment, and write_segments writes each clean segment to its own <label>.ss.h5.

Profiles and tracks#

  • backscatter_vs_range / backscatter_vs_sample: per-bin mean, median, std, percentiles and count.

  • along_track_distance_m(ds, fill_nav_stalls=False): cumulative geodesic distance along the track; fill_nav_stalls spreads pings that repeat a navigation fix.

  • build_survey_track(surveys, freq_key, scanline_stride=): nadir track and strided scan-line endpoints as a SurveyTrack.
