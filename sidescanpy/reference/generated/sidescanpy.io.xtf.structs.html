sidescanpy.io.xtf.structs#

XTF binary structures as numpy structured dtypes.

Field names, order and sizes follow the eXtended Triton Format specification, revision 42 (Exail), and agree field for field with the ctypes structures in pyxtf 1.5.0 (checked by the unit tests). All structures are little-endian and packed (no alignment padding); each dtype’s itemsize is asserted at import.

Structures#

  • CHAN_INFO_DTYPE (128 bytes): one channel description in the file header (CHANINFO).

  • FILE_HEADER_DTYPE (1024 bytes): the file header (XTFFILEHEADER) including its first six ChanInfo blocks.

  • PACKET_START_DTYPE (14 bytes): the fields every packet starts with (magic 0xFACE, header type, sub-channel, channels to follow, reserved, total packet byte count).

  • PING_HEADER_DTYPE (256 bytes): the sonar ping header (XTFPINGHEADER); its first 14 bytes are the packet start fields.

  • PING_CHAN_HEADER_DTYPE (64 bytes): the per-channel header (XTFPINGCHANHEADER) that precedes each channel’s samples.

Units as given by the specification (the reader does not convert): times in seconds, ranges in metres, SensorDepth / SensorPrimaryAltitude in metres, angles in degrees, ShipAltitude / ShipDepth in decimetres, coordinates in the units named by the file header’s NavUnits (0 = projected metres, 3 = degrees with X = longitude, Y = latitude). Sound-velocity fields may hold half the true value (some recorders store the one-way factor c / 2).

sidescanpy.io.xtf.structs.SAMPLE_FORMAT_DTYPES#

SampleFormat (ChanInfo, added in X41) to sample dtype. Format 0 (“legacy”) means “use BytesPerSample”, see LEGACY_SAMPLE_DTYPES. Formats 1 (IBM float), 4, 6 and 7 are not supported.

sidescanpy.io.xtf.structs.KNOWN_SAMPLE_FORMATS = frozenset({0, 1, 2, 3, 4, 5, 6, 7, 8})#

SampleFormat values the XTF specification defines (0-8). Any other value is treated as unset, i.e. as 0 (legacy, BytesPerSample): some KleinXlt 3.0 files have 0xFF in the ChanInfo reserved bytes, which include SampleFormat.

sidescanpy.io.xtf.structs.LEGACY_SAMPLE_DTYPES#

BytesPerSample to sample dtype for legacy (SampleFormat 0) data. Samples are read as unsigned integers, as pyxtf does.

sidescanpy.io.xtf.structs.sample_dtype(chan_info)#

Return the sample dtype described by one ChanInfo record.

SampleFormat (X41 and later) takes precedence; format 0 (legacy) falls back to BytesPerSample. A format that disagrees with BytesPerSample is used as given. A value outside KNOWN_SAMPLE_FORMATS (such as 255) is treated as unset, like 0; this logs at DEBUG only, and read_xtf_pings() warns once per file.

Parameters:
chan_infonumpy.void

One record of CHAN_INFO_DTYPE.

Returns:
numpy.dtype
Raises:
ValueError

If the sample format or byte width is not supported (IBM float, formats 4, 6 and 7, or a legacy width other than 1, 2 or 4 bytes).
