sidescanpy.io.dispatch#

Format-dispatching helpers for sonar file ingestion.

Given a list of file paths, pick the right per-format reader/converter by extension and produce a validated SideScanSurvey. Used by any script or caller that wants “just give me a survey from these files” without hand-rolling the .jsf/.sdf/.xtf branch itself.

  • detect_format(), read_and_convert() – raw .jsf/.sdf/ .xtf.

  • read_and_convert_segments() – one raw file into one or more surveys, each with its output stem (XTF files are split at range-setting changes).

  • find_sonar_files() – the raw files in a directory.

  • load_survey() – a .ss.h5 or a raw file, whichever it is.

  • detect_catalog_format(), read_target_catalog() – target catalogs, dispatched on the catalog directory’s own contents.

sidescanpy.io.dispatch.detect_format(input_paths)#

Detect sonar file format from extension; raise on mixed extensions.

Extensions are compared case-insensitively (.XTF is "xtf").

Parameters:
input_pathslist[Path]

Candidate sonar files. All must share the same extension — this function is for the “merge these into one survey” case; batch callers processing files independently should call it once per file instead of once for a whole directory.

Returns:
str

One of: “jsf”, “sdf”, “xtf”.

Raises:
ValueError

If extensions are mixed, or the (single) extension isn’t supported.

sidescanpy.io.dispatch.read_and_convert_segments(path, *, survey_name=None, min_pings=50)#

Read one raw sonar file into one survey per constant-range segment.

A .jsf file gives one survey, exactly as read_and_convert(). .xtf and .sdf files are split at sample-rate (range-setting) changes (split_by_sample_rate(), split_by_sample_rate()) and each kept run is converted on its own, so every survey has the right sample_rate_hz; runs shorter than min_pings are dropped (for XTF, counted in each survey’s xtf_pings_dropped_short_runs attribute).

Parameters:
pathPath

One .jsf, .sdf or .xtf file.

survey_namestr, optional

Base name; defaults to path.stem.

min_pingsint, default 50

XTF and SDF: shortest run kept when a file is split.

Returns:
list[tuple[str, SideScanSurvey]]

(output_stem, survey) per segment, in file order. The stem is the base name for a single segment, else <base>_seg01, <base>_seg02, … (see segment_stem()); each survey is named after its stem.

Raises:
ValueError

Unsupported extension, or an XTF or SDF file whose runs are all shorter than min_pings.

sidescanpy.io.dispatch.find_sonar_files(input_dir, input_format='auto')#

Raw sonar files directly in input_dir (not recursive), sorted.

Parameters:
input_dirpath

Directory to search.

input_format{“auto”, “jsf”, “sdf”, “xtf”}, default “auto”

"auto" returns *.jsf, *.sdf and *.xtf files. .xtf matches in any letter case (.XTF is common); .jsf and .sdf match lower case only.

Raises:
ValueError

Unknown input_format.

sidescanpy.io.dispatch.load_survey(path, *, chunks=None)#

Read path as a survey, whatever it is.

A .ss.h5 (or .h5/.hdf5) file is read with read_survey() (chunks passed through); a raw .jsf/.sdf/.xtf file is converted in memory with read_and_convert() (chunks ignored).

sidescanpy.io.dispatch.detect_catalog_format(source)#

Target-catalog format of the directory source, from its own contents.

Dispatches on the catalog files present, not on the paired survey’s format (a JSF survey can be labelled in SonarWiz and vice versa).

Returns:
str

CATALOG_SDF_KLEIN (Target_*.tgt) or CATALOG_JSF_DISCOVER (*.target).

Raises:
ValueError

Both kinds present (ambiguous), or neither.

sidescanpy.io.dispatch.read_target_catalog(source)#

Read the target catalog in directory source.

Returns (format, targets) with format from detect_catalog_format(). Klein targets come back without a resolved position; see sidescanpy.targets.correlate for resolving them against .ss.h5 files.
