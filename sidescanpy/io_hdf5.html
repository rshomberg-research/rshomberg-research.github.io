HDF5 (.ss.h5)#

sidescanpy stores a whole survey (every frequency and every aux record) in one HDF5 file with the extension .ss.h5. Each group is a NetCDF-4 group written with h5netcdf, so any HDF5 or NetCDF tool can read it, and xarray can open each group without sidescanpy.

The format is not frozen

The layout below may change in any 0.x release before 1.0, and a file written by one 0.x version may not read in a later one. Keep the raw source files and re-convert after an upgrade. The root attribute sidescanpy_version records which version wrote a file.

from sidescanpy.io.hdf5 import read_survey, read_survey_pings, write_survey

write_survey(survey, "line_001.ss.h5")
survey = read_survey("line_001.ss.h5")
survey = read_survey("line_001.ss.h5", chunks={"ping": 256})   # lazy, dask-backed
survey = read_survey_pings("line_001.ss.h5", start=0, stop=500) # a run of pings

write_survey refuses to overwrite an existing file unless overwrite=True. processing.correct_file corrects a file in place, writing to a temporary file and renaming it so an interrupted run never leaves a half-written survey.

Layout#

line_001.ss.h5
├── /                        root attributes (below)
├── frequencies/
│   ├── hz_100000/           one group per frequency: a SideScanFrequencyChannel
│   └── hz_400000/
└── aux_streams/
    ├── navigation/          always written, empty if the file had none
    ├── attitude/            always written, empty if the file had none
    ├── dvl/                 always written, empty if the file had none
    └── sensors/             only if the survey has sensor records
        └── pressure/

Per-ping variables carry their units in the name suffix (_deg, _m, _ms) rather than a units attribute.

Aux groups#

Aux records have their own time on an obs dimension, independent of the pings, because sensors update on their own schedules.

Group

Variables

navigation

latitude, longitude, and where recorded heading_deg, speed_knots

attitude

roll_deg, pitch_deg, heave_m, and where recorded heading_deg

dvl

altitude_m

sensors/<type>

sensor-specific; pressure holds depth, sound speed and temperature

Each group has a source attribute naming where its values came from (for example extracted_from_xtf_ping_headers).

Encoding#

  • Variables with two or more dimensions are gzip level 4 with shuffle, chunked 256 pings at a time. Per-ping variables are uncompressed.

  • float64 is stored as float32, except latitude and longitude, where float32 resolves only about 0.4 m.

  • read_survey(path, chunks={"ping": 256}) matches the on-disk chunks; other chunk sizes work but read more than they need. Aux records always load into memory (they are small).

  • Files from 0.5.0 may also carry backscatter_raw; they still read, and correct_file drops that variable when it rewrites the file.

Reading without sidescanpy#

import xarray as xr

ds = xr.open_dataset("line_001.ss.h5", group="frequencies/hz_400000", engine="h5netcdf")
nav = xr.open_dataset("line_001.ss.h5", group="aux_streams/navigation", engine="h5netcdf")

From the shell, h5ls -r line_001.ss.h5 lists every group and variable and h5dump -A line_001.ss.h5 prints the attributes.

For one frequency on its own, as a plain NetCDF file, see NetCDF.
