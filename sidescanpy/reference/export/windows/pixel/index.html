    sidescanpy.export.windows.pixel¶

    Sample/ping pixel-space windows: chips, full-channel views, co-located targets, and the per-style window used by the uncorrected/db/ radiometric render levels.

    The low-level functions operate on plain 2D (n_pings, n_samples) arrays -- a caller has already selected the channel and backscatter variable (e.g. ds["backscatter_intensity"].isel(channel=0).values). Row = ping index, column = sample index throughout. :func:extract_pixel_style_window works on a loaded, nadir-masked ping neighborhood and handles all three styles.

    2026 rshomberg@uri.edu

    WindowExtent dataclass ¶

    A window's placement in its source array's native (row, col) space.

    RenderedWindow dataclass ¶

    One rendered export window, before the 8/16-bit display transform.

    Display-oriented float window at its output size.

    Targets inside the window, in image's pixel coordinates (sample = column, extra_attributes["window_row"] = row).
    extent WindowExtent or None

    Pixel levels: the window's placement in the file's ping axis and the style's column space (single-channel samples, or the combined columns of :func:combine_channels_mirrored), before orientation.
    meta dict or None

    Geometric/georef levels: the extractor's meta (grid origin and resolution) for locating further points in the window.
    grid_shape tuple of int or None

    Geometric/georef levels: (n_rows, n_cols) of the resampled grid.
    resolution_m float or None

    Geometric/georef levels: meters per output pixel.

    extract_chip ¶

    extract_chip(
    array: ndarray,
    center_row: float,
    center_col: float,
    size_px: int,
    *,
    jitter_px: int = 0,
    rng: Generator | None = None,
) -> tuple[np.ndarray, WindowExtent]

    Fixed size_px x size_px crop around (center_row, center_col).

    Non-padding placement: the window shifts inward near an array edge instead of zero-padding, trading perfect centering for "always full real data." jitter_px (default 0, exact centering) randomizes which point the window centers on, so a detector doesn't learn "the target is always dead-center" — the true target position is unaffected, only where the window lands moves.

    If array is smaller than size_px in a given axis, the full available extent on that axis is returned instead (non-square output) rather than padding — confirmed against real per-target survey data where a source catalog's own decoded window can have a hard ping-count ceiling well under a requested chip size. Every caller downstream (CocoImageEntry, write_coco/write_yolo) already carries per-image width/height explicitly, so a dataset with mixed image sizes from this cause is handled correctly, not silently mis-sized.

    Returns:

    Type Description
    (window, extent)

    extract_full_channel ¶

    extract_full_channel(
    array: ndarray,
    *,
    center_ping: float | None = None,
    square: bool = True,
    fixed_ping_count: int = 200,
    jitter_px: int = 0,
    rng: Generator | None = None,
) -> tuple[np.ndarray, WindowExtent]

    Full-sample-axis window spanning a fixed ping span, at native resolution — not resized here. Resize (via :func:resize_to) belongs after a photometric transform (e.g. :func:sidescanpy.export.image.to_uint8) has run on the full native-resolution values, not before it: computing a percentile stretch on an already-downsampled array measures the stretch against a blurred, artificially low-variance distribution and washes the result out (found the hard way — see this function's own history). Every other statistics-computing function in this library (waterfall/ gridded percentile scaling, resample_channel_to_grid's cell aggregation) works the same way: aggregate/stretch against real per-sample values first, resize the result for display second.

    square=True (default): the native ping span equals the channel's own sample count, not a fixed ping count against a differing sample count — avoids the aspect-ratio stretch a fixed ping count would otherwise introduce once the eventual square output is produced. square=False uses fixed_ping_count pings instead.

    center_ping defaults to the array's own midpoint (a full-channel negative sample has no target to center on); pass a target's ping position for a positive sample. jitter_px behaves as in :func:extract_chip.

    Known, deliberately deferred edge case: a survey shorter than the native ping span raises ValueError rather than guessing a workaround (e.g. padding or falling back to non-square) — revisit if a real survey actually hits this.

    Returns:

    Type Description
    (window, extent)

    Native resolution — pass through a photometric transform, then :func:resize_to, in that order.

    resize_to ¶

    resize_to(
    image: ndarray, output_size_px: int
) -> np.ndarray

    Resize an already-photometrically-transformed 2D image (e.g. the uint8 output of :func:sidescanpy.export.image.to_uint8) to a square output_size_px x output_size_px — the deliberately-last step after :func:extract_full_channel + a percentile/gamma stretch, never before it (see that function's docstring for why the order matters). Bilinear resampling, matching this project's own established resize-after-transform precedent.

    sample_negative_window ¶

    sample_negative_window(
    n_rows: int,
    n_cols: int,
    target_positions: list[tuple[float, float]],
    size_px: int,
    min_distance_px: float,
    rng: Generator,
    *,
    max_attempts: int = 200,
) -> tuple[float, float]

    Pick a (row, col) window center at least min_distance_px from every position in target_positions — for no-target negative samples.

    target_positions is a plain list of (row, col) tuples, not Target objects, so callers don't need to build one just to check distances.

    Raises:

    Type Description
    RuntimeError

    If no valid location is found within max_attempts — a dense target catalog relative to n_rows/n_cols and min_distance_px can make this genuinely infeasible; fail loudly rather than silently returning a too-close location.

    targets_within_window ¶

    targets_within_window(
    targets: list[Target], extent: WindowExtent
) -> list[Target]

    Every target from targets whose position falls inside extent, translated to window-local coordinates.

    Reuses the existing Target.sample (column) / extra_attributes["window_row"] (row) convention used by the chip exporters. Targets missing either field are skipped (nothing to place). For multi-target images: every included target becomes its own annotation on the same exported image, not just the one a chip happened to be centered on.

    with_bbox_size_px ¶

    with_bbox_size_px(
    target: Target, scale_x: float, scale_y: float
) -> Target

    Record target.bbox's measured (w, h) in this window's output pixels.

    scale_x/scale_y convert from the bbox's native units (source sample/ping pixels) into output pixels -- 1:1 for an unresized pixel window; meters-per-sample (or per ping) over resolution_m for a geometric/georef window. The result goes in extra_attributes["bbox_size_px"], which COCO/YOLO writers use instead of the shared placeholder box size.

    Returns target unchanged when it has no bbox (a center-only pick keeps the placeholder).

    extract_pixel_style_window ¶

    extract_pixel_style_window(
    masked: Dataset,
    *,
    center_sample: int,
    channel_idx: int,
    local_ping: int,
    ping_offset: int,
    style: str,
    level: str,
    size_px: int,

    placed_combined: list[Target],

    Sample/ping-space window for one style, with the targets inside it.

    chip crops size_px square around (local_ping, center_sample) on channel_idx; single-swath takes that channel's full sample axis over a square native ping span; dual-swath does the same on both channels combined (:func:combine_channels_mirrored). The window is oriented (:func:~sidescanpy.export.orientation.orient_pixel_window) and resized to size_px square if needed, with every co-located target moved to match and its measured bbox recorded (:func:with_bbox_size_px).
